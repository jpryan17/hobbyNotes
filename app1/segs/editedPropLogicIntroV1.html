Propositional Logic

As mentioned in the page introduction, a primary goal of propositional logic is to expose the student to formal science in general, and Boolean logic in particular, on familiar ground.

A rather stilted teacher-classroom interaction is used below to introduce a specific perspective on the formalization of propositional logic appropriate for this level of education: as a game that only cares about being right. The pedagogical key to this presentation is the interactive truth table demo, which gives immediate visual confirmation of an expression's value for any given input.

"Good morning, children. I am Jack, and I am here to talk to you about something really amazing: logic."

In the sea of faces, we see the curious, the skeptical, and a few quiet groans. We press on.

"Any questions?"

A hand shoots up from a mischievous face.

"Yes?"

"Is logic logical?" Giggles echo across the room.

"An interesting question, um..."

"Jill."

"Well, Jill, you just used a clever bit of logic, and I stand corrected. I'm not going to talk about logic. I'm going to talk about a formal logic; specifically, propositional logic.

You see, a formal logic like propositional logic cares far more about being right than being 'logical.' It simply refuses to be wrong. That is why it is always supposing things. It begins by supposing that a proposition is a statement that can be judged as definitively true or false."

"Aren't all statements either true or false?"

"Well, Jill, I think maybe not. There are advanced formal logics where you do not assume every statement must be true or false. Some logicians find that very useful. But whatever is 'logically correct' in the real world, the game of propositional logic strictly supposes that a proposition is always either true or false. There is no middle ground.

In many ways, a formal logic is a game logicians invented to copy a small slice of human decision-making. If you play by the rules, and the game copies logical thinking, then you are thinking logically when you play. You literally cannot be wrong.

But to always be right, you have to suppose a lot of things, and you have to ignore a lot of things. For example, look at these two statements:

  1. It is raining.
  2. It is dark.

We assume our circumstances are simple enough that the questions 'Is it raining?' and 'Is it dark?' can be answered with a clean, absolute yes or no. That assumption turns these statements into propositions.

Crucially, the game doesn't actually care if it is raining or if it is dark. It only cares that each proposition has been assigned a truth value. It supposes these values exist, but it doesn't care if they are factually accurate. Figuring out actual weather isn't the game's job—because if it guessed, it might be wrong."

Naming Variables

Propositional logic provides strict rules for combining propositions into larger expressions. Writing out full sentences every time you want to refer to a proposition is a pain—especially when the only thing we care about is the final true/false value.

To fix this, we give propositions short names:

  • "It is raining" is named P
  • "It is dark" is named Q

The specific names don't matter much. Short is always better. In fact, since we are not in first grade anymore, we can think of any four abstract propositions we want. To keep everyone on the same page, we will universally name our four placeholder propositions p, q, r, and s.

On this digital page, these names are rather magical. When you use them to construct logical expressions, they will appear in a rusty red color. Clicking on any red expression will instantly pull up its interactive truth table.

If you view the truth table for a standalone variable like p, you will see that a single proposition is technically a propositional expression, just a very boring one. The final value of the expression is simply the value of the proposition itself.

The Operators

We can build far less boring expressions using logical operators.

1. The NOT Operator (¬)

Unlike other operators, NOT is an exception: it alters a single proposition rather than combining two. It acts as a reverse switch for truth values (e.g., ¬p).

2. The AND Operator (∧)

An expression joined by AND is true only if both individual propositions are true. It evaluates to false if either piece is false (e.g., p ∧ q).

3. The OR Operator (∨)

An expression joined by OR is true if at least one of the propositions is true. It only evaluates to false if both pieces are entirely false (e.g., p ∨ q).

4. The SAME Operator (↔)

Formally known as equivalence, the SAME operator evaluates to true if both sides share the exact same truth value (both true or both false). It returns false if their values differ (e.g., p ↔ q).

Logical Operation Symbol
NOT ¬
AND ∧
OR ∨
SAME ↔

Nesting and Structure

Just as the NOT operator can reverse a single proposition, it can also reverse an entire nested expression trapped inside brackets:

  • ¬ [p ∧ q]
  • ¬ [p ∨ q]
  • ¬ [p ↔ q]
  • ¬ [¬ p]

Similarly, the other operators can be used to chain separate expressions together:

  • p ∧ [q ∨ r]
  • [p ∧ q] ∨ r
  • ¬ p ∨ q
  • ¬ [¬ p] ↔ p

Impressing Your Parents: Tautologies

"That last expression on the list (¬ [¬ p] ↔ p) is what logicians call a tautology. Now that is a vocabulary word that will impress your parents.

When you go home and they ask what you learned today, casually say: 'Not much, just messing around with logical tautologies.' They will be so flummoxed they might completely forget to ask if you finished your homework."

A few laughs escape from the middle rows.

"A tautology is just a fancy word for a propositional expression that is always true, no matter what individual truth values you feed into its variables.

Look at the third expression on our list: ¬ p ∨ q. This structural pattern is used so incredibly often in mathematics that we give it its own shorthand symbol: p → q. The truth table engine natively recognizes this definition, making the statement [¬ p ∨ q] ↔ [p → q] an absolute tautology.

This operation is called implication (or IF-THEN), denoted by the → symbol. Using our tools, we can easily verify that [[p → q] ∧ [q → p]] ↔ [p ↔ q] is also a perfect tautology."

Commutative and Associative Properties

We use tautologies to cleanly prove the core algebraic properties of our logical operations. For instance, the AND (∧), OR (∨), and SAME (↔) operators are completely commutative. This means the physical order of the variables does not alter the truth value:

  • [p ∧ q] ↔ [q ∧ p]
  • [p ∨ q] ↔ [q ∨ p]
  • [p ↔ q] ↔ [q ↔ p]

Tautologies also verify that these three operations are associative, meaning regrouping the brackets changes nothing:

  • [[p ∧ q] ∧ r] ↔ [p ∧ [q ∧ r]]
  • [[p ∨ q] ∨ r] ↔ [p ∨ [q ∨ r]]
  • [[p ↔ q] ↔ r] ↔ [p ↔ [q ↔ r]]

"Well, this is all fine and good, you might ask, but what is it actually good for?"

"Yes, we might," Jill smiles from the front.

"For one thing, you all just natively learned the core mechanics of Boolean logic. Slip that phrase into your dinner conversation tomorrow night.

Of course, you are not industry experts just yet. Software engineers and scientists routinely use Boolean logic to evaluate expressions constructed from millions of simultaneous variables. We would need a monstrously large truth table to sketch that out by hand.

But we are mastering propositional logic today for a very specific structural reason: a propositional expression provides the clean, unyielding skeletal framework for a formal statement—and formal statements are the absolute bedrock of physical science."
