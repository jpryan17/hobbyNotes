Part 2 — Conceptual Overview: The Three Architectural Models
— Logic & Mathematics, Computation, and Persistence —

To realize our concept presentation standards—moving seamlessly from intuitive prose and interactive visuals to machine-checked formal statements, explicit function rules, and transparent execution—Middle Way Mathematics grounds the curriculum in three interlocking architectural models:

  1. The Logical & Mathematical Model (Ontology): Single-sorted predicate logic, ZF set theory, base sets (𝔹, ℕ, ℝ_ω, ℂ_ω), set constructors, and function rules.
  2. The Computational Model (Calculation Machine): A virtual machine with transparent memory, instruction pointers, and step-by-step pseudo-code interpretation.
  3. The Persistence Model (Relational Schema): Relational database tables organizing formal statements, calculations, examples, and student work into scalable open service hubs.

1. The Logical & Mathematical Model (Ontology)

Middle Way Mathematics depends upon a clean conceptual model that:

  • is based on classical single-sorted predicate logic
  • is based on ZF set theory, with built-in membership (∈) and equality (=) predicates
  • has 4 base sets: Boolean truth values (𝔹 = {0, 1}), and 3 number sets (ℕ, ℝ_ω, ℂ_ω)
  • has two fundamental set constructors: product (×) and directed pair (→)
  • and executable function rules (pseudo-code targeting our context-sensitive calculation machine)

2. The Computational Model & Calculation Engine

The formal statement and the Middle Way pseudocode block (i.e. rule) appear in the conceptual mode. A directed equality is essentially a verified function adorned with a calculator template. A formal statement may not directly correspond to a calculation; for example, the derivative operator needs to be instantiated with a specific function. The pseudocode is interpreted by a self-contained calculation machine that executes all legal operations without relying on external arithmetic or math libraries.

3. The Persistence Model & Educational Resource Hubs

Middle Way Math is an interactive prototype offering proof of concept (PoC) for a modern formal science curriculum. The curriculum includes a proposal for educational resource hubs that provide access to formal verification tools (such as Lean 4), static public web pages (such as this site), and in-situ editing tools (currently available in local development). To support PoC for such an educational hub, this platform is generated from a relational database (PostgreSQL), which serves as its persistent storage. 🛡️ Triangulating the Three Models with Lean 4 Formal Verification

Every foundational concept traverses a rigorous verification pipeline that unites ontology, computation, and persistent delivery:

  • Model 1 (Ontology) → The Formal Scaffold (Scaffold.lean): Our classical single-sorted predicate logic and base sets (𝔹, ℕ, ℝ_ω, ℂ_ω) map directly into Lean 4 inductive types and structures. Rather than relying on non-constructive limit gymnastics, the transfinite continuum (ℝ_ω) and its standard-part shadow map (st: ℝ_ω → 𝔻) project continuous dynamics into a dyadic codomain primed for explicit machine calculation. Key structural bridge theorems—including the Telescoping Fundamental Theorem of Calculus (telescoping_ftc, proved by induction on ℕ), operator identities (D_turn_squared, exp_eigen_property), and infinitesimal halo invariants—are machine-verified directly in the Lean kernel.
  • Model 2 (Computation) → Boundary of Environmental Dependence & Runtime Independence: Middle Way Mathematics maintains an epistemological division of labor between formal proof and explicit execution. Lean 4 certifies that mathematical laws, physical invariants, and operator relationships are logically consistent and well-typed. Meanwhile, our virtual calculation machine executes transparent, human-auditable pseudo-code step-by-step without runtime black boxes. The computation engine strictly avoids continuous calculus libraries, computer algebra packages, and runtime transcendental float approximations (such as IEEE 754 Math.sin or Math.exp). Growth is computed purely via discrete Euler compounding in the dyadic ring, rotations via binary CORDIC pseudo-rotations, and calculus via transfinite differences on ℝ_ω. The engine utilizes the host CPU solely for discrete integer arithmetic (+, -, *, bit-shifts) to evaluate explicit dyadic fractions m / 2^k on the Conway tree 𝔻, avoiding combinatorial string branching while maintaining constructive integrity.
  • Model 3 (Persistence) → Relational Hubs & Dual-Layer Verification Architecture: Our persistent relational database schema (PostgreSQL) catalogs formal statements, verified functions, calculator templates, and educational assets. To serve educational resource hubs efficiently, verification is delivered through a dual architecture:
    • Static Web Production: A build-time generator (genLeanCache) verifies all theorems directly in the Lean 4 kernel and caches pre-computed Q.E.D. ✓ proofs and exact millisecond execution timings (171 verified targets) into client assets. Readers receive instantaneous, kernel-certified truth with zero cloud hosting overhead.
    • Local Interactive Dev: Running npm run leanServer launches a local compiler bridge, enabling curriculum authors and students to modify formal lemmas and re-verify them live against the active Lean 4 kernel.

Where the Curriculum Sits in the Formal Verification Spectrum

In modern interactive theorem provers, formalization depth spans a multi-tier spectrum:

  • Tier 1 (Type Signatures & Ontology Specification): Formalizing the vocabulary, primitive types, and operator signatures to eliminate ambiguous notation.
  • Tier 2 (Axiomatic Semantic Scaffold): Postulating the algebraic continuum (ℝ_ω, ℂ_ω) and standard-part shadow map (st: ℝ_ω → 𝔻) as an authoritative structural blueprint, while formally proving key inductive bridge theorems.
  • Tiers 3 & 4 (Certified Software & Computable Models): Formalizing computational algorithms directly in Lean and proving termination and bit-level semantic equivalence (eval(e) = TrueMathValue(e)) with zero unproven axioms.
  • Tier 5 (Universal Constructive Foundations): Constructing the entire transfinite continuum from scratch out of Dedekind cuts or Conway games across tens of thousands of lines of foundational library proofs (e.g. Mathlib).

The Role of Scaffold.lean: Our formal scaffold sits deliberately at Tier 2 (an Axiomatic Semantic Scaffold). It serves as an authoritative structural contract, verifying key inductive bridge theorems while providing a certified type oracle for all 21 formal curriculum statements.
